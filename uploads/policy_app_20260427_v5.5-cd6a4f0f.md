## 1. 개요 (Overview)

본 문서는 FMS 인스톨러 앱의 비즈니스 운영 규칙을 정의합니다.
어드민 정책서(**v7.1**)와 함께 현장서비스 시스템의 통합 정책 체계를 구성합니다.

---

## 2. 역할 및 권한 정책

### 2.1 접근 권한

| 역할 | 인스톨러 앱 접근 | 어드민 접근 |
| :--- | :---: | :---: |
| **설치기사** | 가능 | 불가 |
| **설치관리자** | 불가 | 가능 |

### 2.2 설치기사 앱 내 권한 범위
- 배정된 서비스 건의 작업 수행 및 완료/작업불가 처리.
- 본인 작업 이력 조회.
- 사진/동영상 증빙 촬영 및 등록.
- 서비스 건 신규 생성, 수정, 취소 권한 없음 (어드민 전용).

## 3. 앱 구조 정책

### 3.1 탭 구조
- *(v2.0)* 하단 탭 바 **2개**: `배정 작업 목록` / `이력`.
- 기존 서비스유형별 4탭(설치/탈거/AS/이력)은 폐지. 배정된 작업을 통합 목록으로 확인하고 서비스유형에 따라 자동 플로우 분기.

### 3.2 배정 작업 목록 정책
- **표시 대상**: 로그인한 설치기사에게 배정된(`ASSIGNED`/`ASSIGNED_TEMP`) 현장서비스 건. *(v4.0)* 임시 등록 상태(`ASSIGNED_TEMP`) 건도 동일하게 노출.
- **정렬**: **작업 요청일 순서** *(v4.0 워딩 변경: 작업 희망일 → 작업 요청일)*.
- **표시 항목** *(v5.0 보강)*: 차량번호 / **차종(차량모델)** *(v5.0 신규)* / 업체명 / 지점명 / 서비스 유형 / **설치형태(OBD/Non-OBD)** *(v3.3 추가)* / **작업 주소** *(v4.0 신규)* / **업체 담당자 연락처** *(v4.0 신규)*.
- *(v5.0)* **차종 표시 정책**: 차량 데이터의 차량모델을 차량번호 하단에 부제 형태로 표시.
- *(v4.0)* **임시 등록 차량 표시**: 차량번호가 `00000000`인 임시 등록 건은 차량번호 옆에 `임시` 배지를 표시.
- *(v4.0)* **업체 담당자 연락처 동작**: 탭 시 전화 다이얼러 자동 실행 (`tel:` 링크).
- **검색**: 차량번호 또는 업체명 또는 지점명. 검색어를 포함하는 결과 표시.
- **상세 진입**: 목록 항목 클릭 시 개별 신청 건 상세 화면으로 이동. **임시 등록 차량의 경우 §4.4 임시 등록 차량 처리 정책 참조.**

## 4. 서비스 유형별 작업 정책

### 4.1 설치 (Installation)

#### 4.1.1 작업 순서 정책

*(v3.0) 설치도 AS와 동일하게 "작업 목록 → 개별 작업 → 증빙 → 검증" 통합 프로세스로 변경.*

1. 배정 작업 목록에서 건 선택 → 작업 상세 화면 진입 (**차종 + 운영팀 메모 + 작업 주소 + 업체 담당자 연락처 표시** *(v5.0 차종 추가)*).
2. `[작업 시작]` → 작업 목록 화면 진입. **임시 등록 차량(차량번호 `00000000`)의 경우 안내 팝업 출력 후 진행 차단** (§4.4 참조).
3. 작업 목록에서 작업 항목 클릭 → 개별 작업 진행:
   - 단말기 모델 선택 (필수)
   - 설정 페이지: 일련번호 입력 + *(v4.0)* **`[Non-OBD 호출]` 버튼**, 총 주행거리, 디지털 차키 / 시동 잠금 (어드민 신청값 자동 표시, 읽기 전용)
   - *(v5.0)* **Non-OBD 차량 `[다음]` 제어**: 차량 설치형태가 `Non-OBD`일 때 **`[Non-OBD 호출]` 성공 완료 전까지 설정 페이지 `[다음]` 버튼 비활성화**. OBD 차량은 본 제약 미적용.
   - *(v3.2) 참조 이미지 — 순서 변경, 모든 이미지 항상 표시:* 상시전원 인가 차량 이미지 → 설치 매뉴얼 이미지 → 컴포넌트 이미지 → 커넥터 이미지
4. 증빙사진 촬영 *(v4.3 재설계)* — §5.2 필수/선택 사진 정책 참조
5. `[완료]` → 작업 목록으로 복귀
6. 작업 목록의 모든 작업 완료 시 `[검증하기]` 버튼 활성화
7. 검증 진행 (§4.1.4 검증 단계 정책 참조)
8. 검증 결과 표시 (11항목) → 재작업 또는 작업 완료 처리

#### 4.1.2 디지털 차키·시동 잠금 설정 연동 정책
- 어드민에서 신규 서비스 신청 시 입력한 디지털 차키 설정 / 시동 잠금 설정 값이 인스톨러 앱 설정 페이지에 **자동 표시**.
- *(v3.1)* 기사는 **읽기 전용으로 확인만 가능** (수정 불가). 수정이 필요한 경우 운영팀을 통해 어드민에서 해당 건을 수정하는 형태로 진행.
- 어드민에서 미설정 시 기본값: 디지털 차키=미설치, 시동 잠금=설치.

#### 4.1.3 참조 이미지 정책 *(v5.1 전면 재정의)*

*(v3.2) 설치 작업 진행 시 (서비스 유형이 설치 / 서비스 유형이 AS이고 단말기 교체 또는 단말기 모델 교체인 경우) 아래 참조 이미지는 **누락 없이 항상 표시**됨.*

- **표시 순서** *(v3.2 변경)*: 상시전원 인가 차량 → 설치 매뉴얼 → 컴포넌트 → 커넥터
- **이미지 출처** *(v5.1 변경)*: 4종 모두 **어드민 설치 매뉴얼 관리 메뉴에 등록된 이미지**를 표시한다. 기존 CarDB 연동 방식은 폐지.
- **상시전원 인가 차량 이미지**: 어드민 설치 매뉴얼 관리 메뉴 연동. *(v5.1)* OBD 설치형태 차량이라도 어드민에 해당 이미지가 등록되어 있으면 표시됨. 이미지 유무는 설치형태가 아닌 어드민 등록 여부에 따름. 연동 이미지 없는 경우: *"해당 차량에 대한 상시전원 인가 안내 이미지가 등록되지 않았습니다. 운영팀에 문의해 주세요."*
- **설치 매뉴얼 이미지**: *(v5.1)* 어드민 설치 매뉴얼 관리 메뉴 연동. 연동 이미지 없는 경우: *"해당 차량에 대한 설치 매뉴얼 이미지가 등록되지 않았습니다. 운영팀에 문의해 주세요."*
- **컴포넌트 이미지**: *(v5.1)* 어드민 설치 매뉴얼 관리 메뉴 연동. 연동 이미지 없는 경우: *"해당 차량에 대한 컴포넌트 이미지가 등록되지 않았습니다. 운영팀에 문의해 주세요."*
- **커넥터 이미지**: *(v5.1)* 어드민 설치 매뉴얼 관리 메뉴 연동. 연동 이미지 없는 경우: *"해당 차량의 시동잠금 관련 설치 안내 이미지가 등록되지 않았습니다. 운영팀에 문의해 주세요."*

- 배경색: 노란색 계열 (#fff8e1), 테두리: #fbbf24
- 아이콘: 경고 삼각형 (⚠, 36px)
- 헤딩: "연동 이미지 없음" (14px, #92400e, bold)

- 화면 진행(이전/다음 버튼)은 이미지 연동 여부와 무관하게 항상 활성화.

#### 4.1.4 검증 단계 정책 (설치/AS 공통) *(v4.0 Non-OBD 분기 추가)*

*(v3.0) 기존 유효성 체크 8단계를 작업 끝의 "검증" 단계로 분리·공통화.*

- **검증 진행 — OBD 모드**: OBD 설정 초기화 → CarDB 설치 → CarDB 결과 체크 → 운행 패킷 유효성 체크 — 기존 8단계와 동일 절차.
  - *(v5.3, v5.4 정정)* **운행 패킷 유효성 체크 1/8~8/8 각 단계 직전**: 해당 단계에 맞는 액션 안내/확인 팝업을 의무 표시한다. **올바른 순서: 1/8 시동 OFF 안내 → 2/8 시동 OFF 확인 → 3/8 LED 1회 점멸 확인(이미지) → 4/8 시동 ON 안내 → 5/8 시동 ON 확인 → 6/8 LED 2회 점멸 확인(이미지) → 7/8 진행 안내 → 8/8 완료+펌웨어 버전**. 기사가 각 단계 팝업에서 응답 전까지 다음 단계 진행이 차단된다. (§4.1.4-C 팝업 정책 참조)
- **검증 진행 — Non-OBD 모드** *(v4.0 신규, v4.3 UI 간소화)*:
  - 진입 조건: 차량 데이터의 설치형태가 `Non-OBD`이거나, 설정 페이지에서 `[Non-OBD 호출]` 버튼으로 단말기 OBD 모드를 Non-OBD로 변경한 경우.
  - *(v4.3)* **패스되는 단계(OBD 설정 초기화 / CarDB 설치 / CarDB 결과 체크 / 운행 패킷 유효성 8단계)는 검증 리스트에 표시하지 않는다.** 시각적 노이즈 제거를 위해 아예 생략하고 안내 카드만 표시한다.
  - *(v5.3 추가)* **Non-OBD 검증 화면 상단에 인라인 안내 배너를 항상 표시**한다. (§4.1.4-C 팝업 정책 참조)
  - **시동 ON/OFF 테스트** (운행 패킷 유효성 8단계 대체):
    - **시동 ON 테스트**: 차량 시동 ON 후 단말기 `activation 패킷` 수신 시 패스.
    - **시동 OFF 테스트**: 차량 시동 OFF 후 단말기 `trip 패킷` 수신 시 패스.
    - *(v5.3 추가)* 각 테스트 버튼 상단에 인라인 안내 텍스트를 표시하고, 버튼 클릭 후 대기 중에는 스피너 + 안내 텍스트를 표시한다. 타임아웃 시 EX-12/EX-13 오류 팝업을 표시한다.
  - *(v4.3)* **진행 순서**: 시동 ON 테스트 → 시동 OFF 테스트 → (시동잠금 설치 건) 시동잠금 제어 검증 → 검증 결과. 시동 OFF 완료 시점에 시동잠금 섹션이 자동 노출되며 스크롤로 자연스럽게 이동한다.
  - 시동잠금 제어 검증은 OBD 모드와 동일하게 별도 버튼으로 수행 (시동잠금 설치 건 한정).
- *(v3.2)* **설치형태별 CarDB 처리**: 검증 시 차량 데이터의 설치형태를 체크. OBD → CarDB 정상 여부 검증. Non-OBD → CarDB 정상 여부 패스.
- *(v3.2)* **시동잠금 제어 검증**: 운행 패킷 유효성 체크 8단계 완료 후, **시동잠금 제어 검증을 별도 버튼**(`[시동잠금 테스트]`)으로 진행. 시동잠금 설치 건에 대해 시동 잠금/해제 테스트를 수행.
  - *(v5.3 추가)* `[시동잠금 테스트]` 버튼 상단에 "시동이 완전히 꺼진 상태에서 버튼을 눌러 주세요" 인라인 안내 배너를 항상 표시한다. 테스트 실패 시 EX-05 오류 팝업을 표시한다.

#### 4.1.4-A Non-OBD 호출 정책 *(v4.0 신규, v4.2 노출 조건 보강)*

- 설정 페이지의 단말기 일련번호 입력 인풋 우측에 `[Non-OBD 호출]` 버튼을 신설.
- **노출 조건** *(v4.2 신규)*: **차량 데이터의 설치형태가 `Non-OBD`인 경우에만 본 버튼이 렌더링**된다.
  - 차량 설치형태가 `OBD`인 경우: 버튼 자체가 설정 페이지에 표시되지 않으며, 표준 OBD 검증 플로우(CarDB 설치 + 운행 패킷 유효성 8단계)가 강제 적용된다.
  - 차량 설치형태가 `Non-OBD`인 경우: 버튼이 노출되고, 기사가 필요에 따라 호출하여 단말기 OBD 모드를 Non-OBD로 변환할 수 있다.
- 본 버튼 클릭 시 해당 단말기의 OBD 모드를 Non-OBD로 즉시 변환한다 (어드민 GNB의 `Non OBD 설정` 기능과 동일 동작).
- 호출 결과(성공/실패)는 버튼 하단에 즉시 표시되며, 검증 단계 분기에 즉시 반영된다.
- **단말기 단위 변환**: 본 호출은 단말기 단위 OBD 모드 변경이며, **차량 데이터의 설치형태와는 분리**된다.
- **검증 결과 표시 항목** (11개) *(v3.5 변경)*:
  1. 단말기 기종 / 2. 단말기 SN / 3. 디지털차키 설치 여부 / 4. 시동잠금 설치 여부
  5. GPS 좌표 / 6. 총 주행거리 / 7. 연료잔량
  8. 단말기 전원연결 결과 / 9. 시동감지 결과 / 10. **시동잠금 제어 검증 결과** / 11. GPS 감도 확인 결과
- **GPS 음영지역 처리**: GPS 감도 비정상 시 "음영지역" 체크박스 제공. 체크 시 완료 가능.
- **완료 조건**: 단말기 전원연결/시동감지 중 하나라도 비정상 → **완료 불가**. GPS 감도 제외 전체 정상 → 완료 가능.

### 4.1.4-B 검증 결과 페이지 UI 정책 *(v5.0 신규)*

- **차량번호·차종 헤더 표시**: 검증 결과 페이지 최상단에 현재 작업 중인 **차량번호 + 차종(차량모델)** 을 크게 표시한다. 예: `08허1234 / 현대 포터2`.
- **3버튼 구성**: 검증 결과 하단에 **`[재검증]` / `[재작업]` / `[작업 완료]`** 버튼을 배치.
  - **`[재검증]`**: 설치 프로세스를 재진행하지 않고 검증 단계만 다시 실행. 클릭 시 §4.1.4-C 팝업 정책에 따라 팝업이 다시 표시되며 검증 프로세스가 재수행된다. 증빙사진·설정 입력값(일련번호·주행거리)은 유지된다.
  - **`[재작업]`**: 기존 정책(BR-02)과 동일. 설치 프로세스 전체 재진행 + 증빙사진 재촬영(재작업 모드, 갤러리 첨부 허용).
  - **`[작업 완료]`**: 모든 완료 조건 충족 시에만 활성화.
- **`[재검증]` 활성화 조건**: 검증 11항목 중 **단말기 전원연결 / 시동감지 / 시동잠금 제어 검증** 중 하나 이상 비정상일 때 활성화. 전체 정상(GPS 제외)인 경우 `[작업 완료]`만 활성화되고 `[재검증]`은 비노출.

#### 4.1.5 설치형태 변경 시 작업 초기화 정책 *(v3.3 추가)*
- 작업 진행 중 해당 차량의 설치형태가 운영팀에 의해 변경된 경우, 인스톨러 앱에서 해당 작업을 **초기화**한다.
- 기사에게 설치형태 변경 사실을 안내하고 변경된 설치형태 기준으로 재작업을 진행하도록 안내한다.

#### 4.1.6 운영팀 메모 표시 정책
- 어드민에서 입력한 메모 내용이 인스톨러 앱 작업 상세 화면에 읽기 전용으로 표시됨.
- 기사가 현장에서 운영팀의 지시사항·특이사항 확인 가능.

#### 4.1.7 디지털 차키 정책 (TBD)
- 현재 디지털 차키 제조사 폐업으로 신규 설치 중단 상태.
- 기존 설치 건은 고장 시 탈거 처리.
- 항목 유지/제거는 사업 방향 결정 후 반영.
- **현재 상태**: 모든 기사가 `[미설치]` 선택 중.

### 4.2 탈거 (Removal)

#### 4.2.1 작업 순서 정책
1. 배정 작업 목록에서 건 선택 → 상세 화면 진입
2. 탈거 확인 팝업 (예/아니오)
3. 탈거 단말기 사진 촬영 (필수)
4. 디지털차키 설치 차량인 경우: 작업 완료 이미지 + 디지털차키 원복 동영상 촬영
5. 탈거 완료 처리

#### 4.2.2 탈거 증빙 정책
- 탈거 완료 전 단말기 사진 촬영 필수.
- 사진 미촬영 시 완료 처리 불가.

#### 4.2.3 디지털차키 탈거 정책
- 디지털차키가 설치되어 있는 차량의 탈거 시:
  - **작업 완료 이미지** 필수 촬영.
  - **디지털차키 원복 동영상** 필수 촬영 (기사가 원복 작업 완료 선택 시).

#### 4.2.4 데이터 변경 정책
- STAFF 현장서비스 > 탈거: 상태값 → 작업 완료, 작업 완료 일시, 작업자명 기록.
- 차량 관리: 탈거일 업데이트.

### 4.3 AS (After-Service)

#### 4.3.1 AS 요청사항 정책
- 어드민에서 AS 신청 시 **요청사항을 사전 지정** (9개 항목 중 선택):
  1. 단말기 단순 교체 / 2. 단말기 모델 교체 / 3. 메인 케이블 교체
  4. 안테나 교체 및 조정 / 5. 시동제어릴레이 교체 / 6. 배선 재연결
  7. 설치형태 변경(OBD/Non-OBD) / 8. 디지털 차키 탈거 / 9. 직접입력
- **1개 이상 필수 선택** (무선택 AS 불가). 복수 선택 가능.

#### 4.3.2 AS 요청사항별 완료 정책
- **각 항목은 독립적으로 완료 처리 필요**.
- 전체 지정 항목이 모두 완료되어야 AS 건 완료 가능.

#### 4.3.3 단말기 단순 교체 / 단말기 모델 교체 정책
- **설치 작업과 완전히 동일한 프로세스**를 진행.
- 검증 단계에서 §4.1.4 검증 단계 정책 및 §4.1.4-C 팝업 정책 동일하게 적용.

#### 4.3.5 안테나 교체 및 조정 정책
- 교체 후 GPS 감도 확인 필수.
- GPS 감도 기준: 녹색(정상) / 주황(보통) → 완료 가능. 빨간(불량) → 음영지역 체크 또는 재교체.

#### 4.3.6 시동제어릴레이 교체 정책
- 교체 후 시동 잠금/해제 테스트 실행 (설치 플로우와 동일).
- 릴레이 배선 위치 사진 촬영 필수.

#### 4.3.7 디지털차키 탈거 AS 정책
- 탈거 작업 후 **작업 완료 이미지** 필수 촬영.
- **디지털차키 원복 동영상** 필수 촬영 (기사가 원복 작업 완료 선택 시).

#### 4.3.8 기타 요청사항 정책 (메인케이블/배선/설치형태)
- 해당 작업 수행 후 **작업 완료 이미지** 필수 촬영.

#### 4.3.9 AS 데이터 변경 정책
- STAFF 현장서비스 > AS: 상태값 → 작업 완료, 작업 완료 일시, 작업자명 기록.
- 차량 관리: 최근 설치일 업데이트.
- 단말기 교체 시: 작업 전/후 단말기 정보가 어드민 상세 팝업에 함께 표시됨.

### 4.4 임시 등록 차량 처리 정책 *(v4.0 신규)*

- **임시 등록 차량 정의**: 차량 정보(차대번호/차량번호) 미확정 상태로 신청된 건. 차량번호 `00000000`으로 자동 부여, `is_temporary=true` 플래그 마킹. 상태: `PENDING_TEMP`/`ASSIGNED_TEMP`.
- **배정 작업 목록 표시**: 임시 등록 차량은 차량번호 옆에 `임시` 배지를 표시.
- **`[작업 시작]` 차단 및 안내**: 팝업 문구: "해당 차량은 카코드 확인이 필요합니다. 운영팀에 차대번호 전달 및 문의 부탁 드립니다." / 버튼: `[확인]` (단일). 클릭 시 작업 상세 화면 유지.
- **임시 등록 차량은 작업불가 처리 가능**: 현장 사유로 작업이 불가한 경우 `[작업 불가]` 버튼으로 UNABLE 처리 가능 (§6 작업불가 정책).

## 5. 사진/동영상 증빙 정책

### 5.1 촬영 방식 *(v4.3 재설계)*

#### 5.1.1 촬영 모드 — 시스템 자동 판단 *(v4.3 변경)*
- 증빙사진 페이지는 **최초 촬영 모드**와 **재작업 모드** 두 가지가 있으며, **시스템이 자동으로 판단**한다.
- **최초 촬영 모드**: 처음으로 증빙사진 페이지에 진입한 경우. **카메라 촬영만** 허용.
- **재작업 모드**: 검증 실패 후 기사가 `[재작업]` 버튼을 눌러 재진입한 경우. **카메라 촬영 + 갤러리 첨부** 모두 허용.
- 기사가 수동으로 모드를 토글하지 않는다. 시스템이 `photoMode` 플래그로 관리.

#### 5.1.2 촬영 UX — 항목별 버튼 구성 *(v4.3 변경)*
- **최초 촬영 모드**: 미촬영 항목 `[촬영하기]` 버튼만. 촬영 완료 항목 썸네일 + `[재촬영]`.
- **재작업 모드**: 미촬영 항목 `[촬영하기]` + `[첨부하기]`. 촬영 완료 항목 `[재촬영]` + `[첨부하기]`.
- 증빙사진 페이지 상단에 현재 모드 안내 배너 표시.

## 5-1. 취소 알림 수신 처리 정책 *(v3.3 추가)*

- 어드민에서 `ASSIGNED` → `CANCELLED` 전환 시, 해당 설치기사에게 취소 푸시 알림이 발송됨.
- **앱 측 처리**:
  - 푸시 알림으로 취소 사실 안내.
  - 배정 작업 목록에서 해당 건 **자동 제거**.
  - 기사가 해당 건의 작업 상세 화면에 진입해 있는 경우, 취소 안내 팝업 표시 후 목록으로 복귀.

## 6. 작업불가(UNABLE) 처리 정책 *(v4.0 권한 명시, v5.0 증빙사진 필수)*

### 6.0 처리 권한 *(v4.0 신규)*
- **작업불가 처리는 본 인스톨러 앱(설치기사) 전용**이며, 어드민 측 작업불가 처리 권한은 폐지됨.

### 6.1 작업불가 사유 *(v3.4 변경: 선택형으로 통일)*
- 차량 부재 (노쇼)
- 차량 키 부재
- 통신 불가 지역
- 기타 현장 사유 (선택 시 상세 사유 텍스트 입력)

### 6.2 처리 규칙 *(v5.0 증빙사진 필수 첨부, v5.2 어드민 연동 명확화)*
- 작업불가 처리 시 **사유 선택 필수 + 증빙 사진 1장 이상 카메라 촬영 필수**(최대 5장).
- 증빙 사진은 **카메라 촬영만 허용**(갤러리 첨부 불가).
- STAFF(어드민)에 "작업불가(`UNABLE`)" 상태로 기록. *(v5.2)* **작업불가 증빙 사진은 어드민 상세 팝업의 "작업불가 증빙" 섹션에 사유와 함께 노출됨**.
  - 썸네일(최대 5장) 형태, 클릭 시 원본 크기 보기.
  - 구 버전 앱 처리 건: 어드민에서 작업불가 증빙 사진 섹션 미표시.
  - **인스톨러 앱 작업불가 증빙 사진**과 **운영팀 운영 완료 증빙 사진**은 별도 섹션으로 완전히 분리.
- **작업불가 건은 종결 처리**. 재방문 시 신규 서비스 건으로 등록.
- **인스톨러 앱 이력에도 작업불가 건 표시** (방문비 정산 근거 자료).
- *(v5.3 추가, v5.5 갱신)* **검증 단계 오류 팝업(EX-02·EX-14·EX-15·EX-03·EX-12·EX-13)에서 `[작업 불가]` 버튼 제공**: 검증 실패로 인해 현장에서 작업을 진행할 수 없는 경우, 해당 팝업에서 직접 작업불가 처리 시트로 이동 가능.
- *(v5.5 신규)* **단계별 재시도 정책**: `[재시도]` 버튼은 오류 발생 단계부터 재진행. 이미 완료된 상위 단계는 재수행하지 않음 (EX-02 → step 0 / EX-14 → step 1 / EX-15 → step 2 / EX-03 → 6/8 팝업 복귀).

## 7. 이력 관리 정책

### 7.1 이력 조회 범위
- **본인 작업 건만 조회 가능** (설치기사 개인 이력).

### 7.2 이력 검색 및 정렬
- **검색**: 차량번호 또는 업체명 또는 지점명.
- **연월별 sorting**: `yyyy년` / `mm월` 선택. 기본값: `전체`.
- **정렬 기준**: 작업 완료일 순서.

### 7.3 이력 목록 표시
- 표시 항목: 차량번호 / 업체명 / 지점명 / 서비스 유형 / 작업 완료일시 / **작업완료 여부** (`완료` / `작업불가`).

### 7.4 이력 상세 정보
- **증빙사진 표시**: *(v2.0)* 수정 가능 — 사후 사진 교체/추가 허용.
- **서비스 유형이 설치 또는 AS인 경우**: 단말기 기종 / 단말기 SN / 디지털차키 설치 여부 / 시동잠금 설치 여부 / GPS 좌표 / 총 주행거리 / 연료잔량 / 단말기 전원연결 결과 / 시동감지 결과 / 시동잠금 제어 검증 결과 / GPS 감도 확인 결과.
- **서비스 유형이 탈거인 경우**: 증빙사진만 표시.

### 7.5 취소 건 이력 정책
- *(v3.3)* 취소 건은 인스톨러 앱 이력에 **표시하지 않음**. 어드민에서만 확인 가능.
- 작업불가(UNABLE) 건은 이력에 표시됨 (방문비 정산 근거).

### 7.6 실패 이력 정책
- 실패 건은 이력에 표시되나, 실질적으로 대부분 재설치로 해소됨.
- Non-OBD 실패: CarDB 미설치로 인한 오류. 운영팀 확인 후 어드민(STAFF)에서 처리.

## 8. 네트워크 정책

- **온라인 전용**: 인스톨러 앱은 Always Online으로 동작.
- 단말기 유효성 체크, 사진/동영상 업로드, 작업 완료 처리 모두 서버 통신 필수.
- 네트워크 단절 시 작업 진행 불가 안내.
